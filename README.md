# dsh-draw-meme · 表情包绘制

装完就能让大肥鱼自己画表情包：一句话出图、自动压暗、自动加中文、直接进表情库。

**不需要 ComfyUI。** 只要有 DSH 和 Python 3.10+（带显卡最好，不带也能跑）。

---

## 装

### 方式一：用 dsh 命令（DSH 自带 CLI 的机器）

```bash
dsh plugin --profile <你的 profile 名> add <本目录的绝对路径>
```

它会自己把依赖项和 bundle 写进 profile，重启后生效。

### 方式二：手动装（没有 CLI 也能装）

1. 把**整个目录**复制到（`models/` 里没有权重，LoRA 要另外下载，见下面「怎么装这个 LoRA」）
   目标是（把 <profile 名> 换成你自己的）：
   `~/.dsh/profiles/<profile 名>/node_modules/dsh-draw-meme/`
2. 打开同级的 `package.json`，加两处：

```json
{
  "dependencies": {
    "dsh-draw-meme": "file:<本目录的绝对路径>"
  },
  "dsh": {
    "profile": {
      "bundles": [ "...别动...", "dsh-draw-meme" ]
    }
  }
}
```

> 改之前先把 `package.json` 备份成 `package.json.bak-before-draw-meme`。

3. 重启 DSH

### 装完怎么确认

- 工具表里出现 `draw_meme`
- 设置页最下面出现「**表情包绘制**」（client 面板要**重启 + 刷新页面**才出来，只重启不刷新看不到）
- 直接对它说「画一张笑的」，能出图就是成了

### 首次使用会自动准备

1. `pip install` 缺的依赖（torch / diffusers / peft / Pillow / numpy / safetensors）
   —— 装进**运行它的那个 Python**，不是插件自带 venv
2. 从 `hf-mirror.com` 下 SDXL 底模 animagine-xl-4.0（约 7G，缓存到 `~/.dsh/draw-meme/hf/`）

第一次要等（下模型最慢），**别以为卡死了**——`~/.dsh/draw-meme/hf/` 里的文件在变大就说明在下载。
之后每次出图 8~10 秒（显卡）或 1~2 分钟（CPU）。

装到哪、下到哪、每种报错怎么修 → **`docs/首次使用-依赖与模型.md`**（接手前必读）

## 显卡和占用（先把三个数分开）

| 说的是什么 | 需要多少 | 说明 |
| --- | --- | --- |
| **显存** | 约 **6.5G**（低显存档约 **0.95G**，见下） | 跑图时占显卡的量。8G 卡能跑，6G 卡会紧张；显存不够就开低显存档 |
| **硬盘** | 约 **10G** | 首次下载底模 7G + torch 2.5G，之后不再涨 |
| **内存** | 8G 以上 | 加载模型时的系统内存，不占显卡 |

这三样经常被混成一个「要 10G」，其实不是一回事。

**显卡分三档：**

- **N 卡（CUDA）**：开箱能用，实测 832×832 一张约 4 秒。
- **A 卡（AMD）**：Windows 上要分两说。RX 6000 这一代（gfx1031，比如 6700/6750 XT）
  在 AMD 官方支持的 HIP SDK 表里是**不支持**；社区自己编译的 ROCm 构建能跑起来，
  但驱动、版本、坑都要自己处理，不是装完就能用。
  之前我口头说过「A 卡只能 CPU 硬跑」，这话不准确，收回。
- **没独显**：走 CPU，一张 1~2 分钟，能用但别指望速度。

### 显存不够怎么办：低显存档

设置页有个「低显存档」开关，勾上就走 comfy 自带的最低显存档：

| | 普通档 | 低显存档 |
|---|---|---|
| 峰值显存 | 7.55G | **0.95G** |
| 832×832 每张 | 3.3 秒 | **7.7 秒**（慢 2.3 倍） |
| 走底图 | 是 | **是**（同一套底图库、同样从第 2 步接手） |
| 画质 | 基准 | **几乎一致**（同底图同种子实测平均像素差 0.36%） |

原理：它**不换模型、不量化、不降精度**，只是把权重留在内存里，采样时一层层搬上显卡、用完就卸
（`comfy.cli_args.args.novram = True`，也就是 comfy 自己的 "no vram" 模式）。所以算出来的数值是原样的，
画质自然一样；代价全在搬运时间上。

它还有一档轻一点的 `lowvram`（文本编码器走 CPU）：实测峰值 6.0G、31 秒，省得不够，所以默认用最省的那档。

**不会影响普通档**：这个开关默认关着，关着的时候 comfy 的启动参数和以前一个字节都不差。
旧的 diffusers 补充包（`python/lowvram/`）还留着当退路，但**不再自动启用**；想退回老方案就把
`lib/host.js` 里那行 `env.DSH_COMFY_LOWVRAM = '2'` 换成 `env.DSH_DRAW_LOWVRAM = '1'`。

## 省算力：低分辨率 / 低步数 / 像素风（实测）

同一个 seed、同一个 LoRA，只改分辨率或步数（RTX 5080 16G）：

| 档位 | 耗时 | 画质 |
| --- | --- | --- |
| 832×832 / 15 步（默认） | 采样 2.07 秒 | 正常 |
| 832×832 / 28 步 | 采样 3.90 秒 | 细节更足，速度慢一倍 |
| 384×384 / 8 步 | 1.0 秒 | 单人，头箍围裙鲸尾鳍耳都在，能认出是角色 |
| 320×320 / 8 步 | 0.97 秒 | 能认，边缘有青块 |
| 256×256 / 8 步 | 0.99 秒 | 糊，只剩蓝发加白围裙的轮廓 |
| 512×512 / 8 步 | 1.7 秒 | 反而容易出双人、发色爆蓝，不建议 |

**384 往下不会更快**：文本编码、VAE 解码、存盘这些固定开销已经占满，约 0.9 秒。

步数也一样（384×384）：8 步 1.04 秒可用，4 步 0.81 秒勉强能认，
**2 步 0.40 秒、1 步 0.29 秒全是噪点** —— 这个 LoRA 不是照低步数训练的，别硬压。

**想要像素风**：384 出图之后压到 96×96、量化到 16 色、再最近邻放大，
就有 96px 宽的精灵感，前后约 1.2 秒（纯 Pillow，不占显存）。
手绘精灵那种干净描边和手工点的瞳孔高光，模型给不了，得多抽几张挑一张。

## 把它传到 GitHub（给维护者看的）

包里有个 456M 的 LoRA（`models/dafeiyu_v24.safetensors`），**超过 GitHub 单文件 100M 限制**，
直接 `git add` 会被拒。两种办法：

**1. Git LFS（推荐，别人 clone 就能用）**

```bash
git lfs install
git lfs track "models/*.safetensors"
git add .gitattributes
git add models/dafeiyu_v24.safetensors
```

**2. 放 Release 附件（仓库里不带权重）**

`.gitignore` 默认已经忽略 `models/*.safetensors`。把 LoRA 传成 Release 资产，
装机的人下载 → 解压 → 放进 `models/`（步骤见上面「怎么装这个 LoRA」）。少了它插件照样能跑，只是画出来的不是大肥鱼。

`.gitignore` 已经排掉：`out/`、`tmp/`、`torchinductor_*/`、`__pycache__/`、`*.bak*`、`models/*.safetensors`。

**3. `comfy_kit/` 怎么办（195M、824 个文件，里面有个 128M 的 hip 后端）**

它是运行时必需的——插件靠它不用装外部 ComfyUI。但它自己也有单文件超 100M，所以和 LoRA 一样不能直接进仓库：

- **想让人 clone 完就能跑**：`git lfs track "comfy_kit/**"`，仓库会因此重很多。
- **想保持仓库干净**：把 `comfy_kit/` 压成一个 zip 挂 Release，README 里写清「解压到插件根目录」。
  N 卡用户其实用不到那个 128M 的 hip 后端（那是给 AMD 卡的），压缩包能小一截。

两条路都行，选一条写进仓库说明。**没定之前别推**——202M 的东西推上去再删，历史里也还是留着。

### 怎么装这个 LoRA（必看）

1. 打开仓库的 **Releases** 页面（右边栏）
2. 下载 `dafeiyu_v24.zip`（456M）
3. **解压**，里面是 `dafeiyu_v24.safetensors`
4. 把它放进插件的 `models\` 目录，最终路径长这样：

```
...
ode_modules\dsh-draw-meme\models\dafeiyu_v24.safetensors
```

5. 重启 DSH（或等 12 分钟让常驻进程自己退掉）

**文件名必须一字不差**是 `dafeiyu_v24.safetensors`，改了名插件就找不到。

放好之后再画一张，日志里应该出现：

```
loading LoRA dafeiyu_v24.safetensors ...
```

没有这一行、反而出现「警告：没找到大肥鱼 LoRA」，就是路径放错了。

### 底模到底怎么来（三种情况）

底模是那个 6.5G 的 `animagine-xl-4.0`，管「会不会画」；LoRA 只教「画成什么样」。三种情况选一种：

**情况一：什么都不配（省事）**

首次出图时插件会自己从 `hf-mirror.com` 下载，约 7G，缓存在：

```
~/.dsh/draw-meme/hf/
```

下完之后就不再联网了。第一次出图会卡在下载上，等它下完就行。

**情况二：硬盘里已经有了（推荐）**

ComfyUI / WebUI 用户大概率有现成的 `animagine-xl-4.0.safetensors`。填绝对路径就行，
在设置页的「底模」那一栏，或者直接写配置文件：

```json
{ "base": "D:/ComfyUI/models/checkpoints/animagine-xl-4.0.safetensors" }
```

省掉 7G 下载。

**情况三：下载老是断**

手动去 hf-mirror.com 搜 `cagliostrolab/animagine-xl-4.0`，下载
`animagine-xl-4.0.safetensors`，然后按情况二配。

> 换别的 SDXL 底模也能跑，只是画风会变——LoRA 是相对 animagine 训的，
> 换底模等于换画风。

## 为什么提示词要拆三段

CLIP 的文本编码只有 **77 个位置**，超了不报错、直接从尾部砍掉。

v17 那套提示词实测 **137 个 token**，被砍掉的正好是最后那截——动作词和白底词，
所以以前的图「动作出不来、背景不白」。这不是模型不行，是提示词压根没进去。

现在的做法：拆成三段分别编码，再把 embedding 拼起来（UNet 的 cross-attention 不限制长度）。

- 发色只写发根，不写发梢（写「lighter tips」发梢会漂成亮蓝）
- 负面 embedding 复制三份补齐长度，不然 CFG 会报 shape 不匹配
- 纯 txt2img，不做 img2img 重绘（重绘会磨掉清晰度，还慢 6 倍）

单张约 4 秒（首张含加载模型约 28 秒），显存约 6.5G。

## 出图不稳定是正常的

为了保证速度（单张约 4 秒），模型跑在很紧的配置上，所以**废片是常态**：

| 现象 | 大约比例 | 说明 |
|---|---|---|
| 偶尔出现两只大肥鱼 | 6% 左右 | 训练集里拼图表情包太多 |
| 图上冒出假汉字乱码 | 10% 左右 | 训练集带字的图太多，负面词压不住 |
| 画得明显不对（脸崩、手崩） | 4% 左右 | 采样器差异 |

**建议一次出 2~3 张，挑一张用。** 不要只出 1 张就下结论。

真在意稳定性的话，就把 `数量` 给到 3，废片率会降到能接受的范围。

- 「出三张：笑、震惊、鼓腮」

## 它做什么

1. 拼提示词（角色段写死，表情动作段按你说的补）
2. 跑 SDXL + 内置的大肥鱼 LoRA（`models/dafeiyu_v24.safetensors`）出图
3. 整图压暗 0.96（纯白背景不动）
4. 贴上中文字（深藏青字 + 白描边，不垫白块、不扩画布）
5. 存进 `~/.dsh/meme-packs/dafeiyu-auto/memes/auto/`
   （那个目录写不进去时自动退到插件自己的 `out/`，宿主再搬回库，图不会丢）

## 可以改的配置

设置页「表情包绘制」里直接改，或者写 `~/.dsh/draw-meme.json`（改完立刻生效，不用重启）：

```json
{
  "python": "C:/Python312/python.exe",
  "base": "D:/models/animagine-xl-4.0.safetensors",
  "lora": "",
  "size": 832,
  "步数": 20,
  "dim": 0.96,
  "seed": null
}
```

| 键 | 说明 |
|---|---|
| `python` | 指定解释器。留空 = 自动找（会跳过 Windows 商店的占位符） |
| `base` | 本地底模 `.safetensors`，或 HF 仓库名。留空 = 下 animagine-xl-4.0 |
| `lora` | 换 LoRA 时用。留空 = 用内置的大肥鱼 v24 |
| `size` | 出图边长，默认 832。**只认 512 / 768 / 832 / 1024**，其它值会被换成配置里的 size；832 不需要缩放底图，最稳 |
| `步数` | **采样总步数，默认 20**。底图库里是「只跑了 2 步」的半成品，所以实际采样 = 步数 − 2 |
| `dim` | 压暗系数。**注意：现在走 comfy 后端，这个参数已经不影响出图**（只留在废弃的 diffusers 分支里），留着是为了老配置不报错 |
| `seed` | 固定种子，想复现某张就填；留空 = 每次随机 |

也可以用环境变量 `DSH_PYTHON` / `DSH_DRAW_BASE` / `DSH_DRAW_LORA` / `DSH_DRAW_STEPS`。

### 步数怎么选（RTX 5080 实测，只算采样，不含 25 秒模型加载）

| 总步数 | 实际采样 | 每张耗时 | 效果 |
|---|---|---|---|
| 5 | 3 | 0.85 秒 | **糊成一团，不能用** |
| 10 | 8 | 1.46 秒 | 完整可用，细节略松 |
| 15 | 13 | 2.07 秒 | 完整，手里的道具偶尔糊 |
| **20（默认）** | 18 | **2.66 秒** | 细节足，道具基本保住 |
| 28（旧默认） | 26 | 3.90 秒 | 细节最足，慢一倍 |

时间跟步数基本线性，每步约 0.15 秒。默认取 20：比旧的 28 步省三分之一，画质上看不出差别。

### 分辨率怎么选（推荐 832，其余能用但有代价）

底图库里存的是 **832 的画布**（104×104 的潜变量）。选别的尺寸时，插件会把这个潜变量
**双线性缩放到对应格子**再接着采样——所以能出，但缩得越远，构图和比例越容易飘。

**832 是唯一不需要缩放的档位，也是最稳的。**

| 边长 | 每张耗时 | 20 张实测崩张 | 画面 |
|---|---|---|---|
| 512 | 1.17 秒 | 0 / 20 | 快，但脸和手发虚、细节明显少；缩放比例 62%，构图偏差最大 |
| 768 | 2.35 秒 | 0 / 20 | 比 512 好一截，接近 832 |
| **832（默认，推荐）** | **2.72 秒** | **0 / 20** | 基准，细节完整，不需要缩放 |
| 1024 | 3.89 秒 | 0 / 20 | 最细（尾巴纹理明显更清楚），但慢 43%；放大比例 123%，偶尔构图偏松 |

**显存跟分辨率几乎无关**：四档峰值都在 8.1G 左右（模型常驻就占 7.2G），显存不是瓶颈，时间才是。

**其它分辨率的副作用，挑重要的说**：

1. **只能填 512 / 768 / 832 / 1024**。填别的数值（比如 640）不会报错，但会被悄悄换成配置里的
   `size`，等于没改——这是为了避免出到模型不会画的尺寸。
2. **非 832 的构图会跟底图不完全一致**。同一张底图在 832 和 512 下，人物在画面里的占比会变，
   不是简单等比缩小。
3. **512 的手部、道具最容易糊**。要贴字的表情包，512 的字会相对更大、更挤。
4. **一批图要成套就别混尺寸**。同一套表情包里混 512 和 1024，放在一起比例会跳。

## 提示词怎么写

见 **`docs/提示词指南.md`**：内置 21 个中文情绪名，外加一个**固定格式**教你自己写新表情
（`<情绪词>, <眉眼>, <嘴>, <手>`，四个位置、从简、别写服装背景）。里面没有逐条现成的英文句子，
给了也会互相污染——照格式自己组，比抄别人的稳。

**当前定稿（2026-11-12）实际拼出来的正面提示词：**

```
(1 dafeiyu:1.2), solo, chibi, big head, short body, (solid royal blue hair:1.5),
long wavy hair, ahoge, <表情动词>, blue eyes, pale pinkish skin,
blue whale fin ear ornaments, navy maid dress, (white apron:1.2),
white maid headdress, large dark blue whale tail, blue tail fin, pure white background
```

底图库现在是 **2 步潜图**：每份 `潜图-<种子>.pt` 旁边有一个 `潜图-<种子>.json`，
里面写 `{"steps": 2}`。插件读这个数字决定从第几步接手（去噪 = 1 - steps/28），
所以换库只要一并带上 sidecar，不用记环境变量；没有 sidecar 时按 `DSH_DRAW_BASE_START`，默认 2。

三条不能动的规矩：数量词最前且与角色名绑定（`(1 dafeiyu:1.2)`）、
颜色不跨部位合并（`hair and eyes` 会变灰白）、身份词一个都不省。

**另有一个动作坑**：手的动作写成复数会画出四只手。
`hands on own cheeks`（双手贴脸）实测会变成「脸侧两只 + 身前两只」，
换成 `hands clasped in front` 或单数写法就正常。细节见 `docs/提示词指南.md`。

想在 ComfyUI 里自己搭同样的流程，见 `docs/技能包.md`（底模、LoRA、步数、色号都在里面）。

## 做不到的地方

- 底模 7G 必须下，省不掉
- CPU 出一张 1~2 分钟
- **中文只能后期贴**，不能让模型写。SDXL 写中文必乱码，别试
- 训练集里带字的图不少，出图偶尔会冒假字/乱码 —— 已知限制，没根治（详见提示词指南坑 6）
- 要不要重启才生效：改 `python/draw.py` **不用**重启（每次出图新起进程）；改 `lib/host.js` 或 `client.js` **要**重启
